# Design decisions

Record each significant decision: what was chosen, what was rejected and why.

| # | Decision | Options considered | Chosen | Reason |
| --- | --- | --- | --- | --- |
| D1 | How rules are enforced | Repair after; train into models; reject and regenerate | Reject and regenerate, shared by all generators | Fair comparison; rejection count becomes a measure |
| D2 | Benchmark data | Public real dataset; published statistics; synthetic reference world | Synthetic reference world | Known ground truth, no personal data |
| D3 | Deep models in Scenario 1 | Train on prior-generated data; exclude | Exclude | Would only relearn the prior |
| D4 | LLM routing | External; local; split | All local, small vs large model | No data leaves the machine; size comparison measures the trade-off |
| D5 | Rule language | Python; SQL; restricted expressions | Restricted expressions | Readable, safe from code injection |
| D6 | Storage | Database; files | Versioned YAML/JSON (MLflow dropped, see 2026-11-13) | Simple for one user, easy to diff |
| D7 | Interface | Web front end; notebook; Streamlit | Streamlit | Fastest route to a usable review screen |
| D8 | Combining schema methods | Best method; weighted vote | Weighted vote with disagreement flags | Uses each method's strengths, makes uncertainty visible |

## Log of later decisions

| Date | Decision | Reason |
| --- | --- | --- |
| 2026-11-10 | Embedding classifier: neighbours vote with similarity^8, learned model gets 20% of the vote | Tuned on the 6 validation schemas (37 columns): 37/37 correct, against 35/37 with plain similarity voting and an even split. The learned model alone scored 19/37, since 116 training columns cover 38 concepts thinly. Test schemas not used for tuning. |
| 2026-11-10 | Gaussian copula and CTGAN written in this project (NumPy/SciPy and PyTorch) rather than taken from SDV or synthcity | synthcity pins older pandas and NumPy versions that clash with this project's; SDV and CTGAN moved to a source-available licence. Both are compact versions of the published methods. |
| 2026-11-10 | Learned approaches share one column preparation (`generators/fields.py`); identifiers and columns with no statistics are filled by the knowledge-based generator for every approach | The comparison is about what each approach learns, not how it makes case numbers. Dependent dates are modelled as a gap after their parent date. |
| 2026-11-10 | Copula, Scenario 1: correlations only from what the calibration store gives (the defended rate by claim type, matched by choosing the latent correlation; columns with identical null rates are missing together); everything else independent | No other joint statistics are visible to generators. Scenario 2: correlation estimated from the sample's normal scores, shrunk 10% towards independence (200 rows give a noisy estimate). |
| 2026-11-10 | CTGAN: 1000 epochs (not the published 300), batch of a quarter of the sample, positive numbers with skew > 1 learned on a log scale | At 300 epochs claim amounts came out far too high (median 10,322 against the sample's 605); at 1000 the median was 736, about 40 s per fit. Checked against the sample only, never the evaluation store. |
| 2026-11-10 | LLM generator: exact counts per batch, worked out so running totals land on the target proportions; identifiers filled in code | Counts are easier for a model to follow than percentages, and correct any drift in the next batch. Models repeat themselves and can echo real-looking references, so uniqueness is left to code. |
| 2026-11-12 | Differences between approaches: paired t-tests across seeds (runs with the same seed form a pair), Holm-adjusted per metric, α = 0.05 | Each approach is a few seeds, so the test has to be simple and stated in advance. Holm controls false positives across the pairs of approaches without Bonferroni's loss of power. A Wilcoxon test was ruled out: with 5 seeds its smallest two-sided p-value is 0.0625, so it could never reach 0.05. When every pair differs by the same amount, no test is reported. |
| 2026-11-12 | The experiment runner uses only approved profiles, saves a copy of the profile in each batch, and skips (with the reason) an LLM approach whose model isn't available | Keeps "people approve, AI proposes" for batch runs too; the copy means a batch can be re-evaluated even if the profile store changes; a missing local model shouldn't stop the other approaches. |
| 2026-11-10 | Dropped the large local model (llama3.3:70b); one local LLM (llama3.1:8b) only | It needs about 43 GB of memory and this machine has 36 GB. D4's small-versus-large comparison is out of scope unless a mid-size model is added later. |
| 2026-11-13 | The knowledge-based generator reads approved rules as generation steps (date order as parent plus a gap, number caps, conditional presence and values, bounds, uniqueness) and draws within groups where the calibration store gives group shares; categories are kept to the profile's allowed values | It is the approach built from written knowledge, so it should use the rules, not just be filtered by them. Rejection stays shared (D1): rules it can't read are still enforced by the validator. On the saved profiles rejections fell to 0 (s08 had 1,734 and an incomplete run). Claim value by claim type is held back for evaluation, so no generator may use it. |
| 2026-11-13 | Trial-generation check before approval: 1,000 knowledge-based rows; a rule the generator builds rows for is flagged if over 1% of the rows it covers fail, a rule it only checks if over 50% fail. A warning, not a block | A rule the generator meets by construction should never fail, so even a small failure share means a conflict (a 50% threshold missed a conflict in a third of the rows). Kept as a warning because the check is heuristic. |
| 2026-11-13 | Experiment plan pinned to `s01-civil-money-claims@7` | The plan must be fixed before results are seen; a pinned version can't change if the profile is edited and approved again. |
| 2026-11-13 | Not implementing Presidio name detection in screening or MLflow experiment tracking | Out of scope for the prototype. Screening stays pattern-based, backed by the user's confirmation that flagged values are made up; runs are tracked in versioned files (each batch's profile copy, run records and `experiment_report/`), which the Report screen already reads. |
| 2026-11-13 | TVAE written in this project (PyTorch), sharing CTGAN's column representation; 2000 epochs, batch of a quarter of the sample; categories drawn from the decoder's probabilities rather than the most likely one | Same reasons as CTGAN (licence, pandas versions); sharing the representation means the two deep models differ only in the model. Checked against the Scenario 2 sample only: at 300 epochs the 90th percentile of claim amounts was 4,274 against the sample's 8,248; at 2000 it was 7,921 (about 20 s per fit). Taking the most likely category gave 97–99% money claims against the sample's 92% (among allowed types); drawing gave about 94%, in line with CTGAN. This departs from the published sampling and is stated as such. |
| 2026-11-13 | `or` rules in the knowledge-based generator: in rows where no alternative holds, one alternative is applied, preferring one that changes a column no other rule changes, then the written order | Taking the first alternative let one rule undo another (an `or` rule emptied hearing dates another rule had filled). Rules with `not (...)` stay with the validator. |
| 2026-11-13 | Column names that aren't a single word (for example `Case Reference`) are written in backticks in rules; dictionary rules quote them automatically | S05's headers have spaces, so the dictionary produced `unique(Case Reference)`, which can't be parsed and crashed the Review screen. Backticks follow the convention of pandas `query`. |
| 2026-11-13 | Steps open in order through a step bar (Upload → Review → Generate → Report) instead of free sidebar navigation | Makes "people approve, AI proposes" visible in the interface: nothing can be generated before a profile is approved in the session. Trade-off: reusing a saved profile or batch means passing through the earlier steps first. |
| 2026-11-13 | Interface follows the "Review · two-pane" mockup: Inter font served from the app (not Google Fonts), soft blue-grey page with white cards, grey theme with black text for the dark choice | Keeps the local-only promise while matching the design; all text colours meet 4.5:1 contrast. |
| 2026-11-13 | The experiment plan's approved profile is kept in `config/profiles/` (a copy of `s01-civil-money-claims` v7) instead of being looked up in `data/profiles/` | `data/` is never committed, so the pinned profile did not exist in a fresh clone and `make experiments` stopped at once. The copy is the same approved profile; the runner still refuses unapproved ones. |
